# Sources and provenance

Reviewed 23 October 2026.

- [Hackathon FAQ](https://amazonappdev2026.devpost.com/details/faqs): Bee entries require actual Bee-device or Apple Watch data. A simulated-only demo is not sufficient.
- [Bee real-time events](https://docs.bee.computer/docs/realtime): official CLI event shape, `new-utterance`, and stream limitations.
- [Bee agentic context](https://docs.bee.computer/docs/agentic-now): account context examples, not a public device-test dataset.
- [Bee API](https://docs.bee.computer/docs/api): authenticated access. The project does not bypass account access controls.
- [Official Bee CLI source](https://github.com/bee-computer/bee-cli): connector reference. Relay invokes an independently installed CLI.
- [Codex non-interactive mode](https://developers.openai.com/codex/noninteractive/): read-only sandbox and JSONL execution. CLI arguments also checked against the installed CLI help.

`samples/bee-documentation.json` and the “Load official sample” button use the documented `Hello there` utterance. That is a schema example, not evidence from the user's hardware. Rehearsals are generated by Relay and explicitly labelled synthetic. A `bee-cli` label indicates the ingestion route, not independent attestation of physical hardware or speaker identity.

The bridge stamps local receipt time. Upstream transcript delivery may be delayed: the freshness guard rejects old submitted timestamps but cannot establish the original audio capture time when Bee provides no capture timestamp. Real deployment must measure this latency and cannot treat transcript availability as a reliable emergency sensor.
